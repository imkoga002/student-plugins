# 始める

講評言語(`.ryukoku/config.yml` の `feedback_lang`)が `en` のときは、学生への応答・問い・説明を英語で書き、タブの名前は英語の組(下の表の右)を使う。

## なぜこの形か
- 学生は、チャットと Claude Docs の画面だけを使う。コマンドを打たず、合言葉もない。
- AI が原稿に書いてよいかは科目の AI 利用条件で決まる(ガイドラインⅢ-3)。その条件を決めるのは学生で、文書の「設定」タブに学生が自分で付けるコメントで決まる。AI のコメントは、Docs のサーバーが AI のもの(`via: mcp`)として記録するので、判断として数えられない。
- 判断(主張カードの確定・VERIFIED・設定・提出の確認)は、すべて学生が画面で付けるコメントで行う。✓ は内容を本文に入れる操作で、判断の証拠ではない(Docs は誰が ✓ を押したかを残さない)。

## 手順
1. 学生に尋ねる(まとめて一度に。推測で埋めない):
   - 論文の題(仮でよい)と、原稿の言語(ja / en)・講評の言語(ja / en。既定は `${user_config.feedback_lang}`)
   - 作業フォルダ(今のフォルダでよいか。ホームフォルダそのものや Plugin の中は不可)
2. 作業フォルダを初期化する(AI が実行してよい道具。学生は何も打たない):
   ```
   bash "${CLAUDE_PLUGIN_ROOT}/scripts/init-project.sh" --dir "<作業フォルダの絶対パス>" --lang ja --feedback ja
   ```
   `${CLAUDE_PLUGIN_ROOT}` が展開されないときは、このスキルの場所から二つ上(`${CLAUDE_SKILL_DIR}/../..`)。既に `.ryukoku/config.yml` があれば初期化は止まる(既存のプロジェクト。`.ryukoku/docs.json` の文書を使う)。
3. Claude Docs の文書を作る。**一回の `batch` で 7 つのタブを作り、名前を下の表のとおりに付ける**(名前が一字でも違うと登録されない)。並びは表の順(`order` を a0〜a6)。最初のタブ(`$lid:f`)を「原稿」にする。

   | 役割 | 名前(ja) | 名前(en) | 最初に置く中身 |
   |---|---|---|---|
   | 原稿 | 原稿 | Manuscript | 題、日付、見出しだけ(はじめに・先行研究・方法・結果・考察・おわりに・参考文献)。本文は書かない |
   | 主張カード | 主張カード | Claim cards | 表: ID / 学生の言葉(原文) / AI の整理 `[ai_suggested]` / 状態。説明一行:「確定は、その行に『C001 を確認』とコメントする」 |
   | 文献台帳 | 文献台帳 | Sources | 表: ID / 識別子(DOI・NCID など) / 書誌 / 実在確認 / 確かめた頁。説明一行:「原典を読んだら『S001 VERIFIED p.12』と頁つきでコメントする」 |
   | 問いと思考の記録 | 問いと思考の記録 | Questions and thinking | 見出し「研究の問い」「思考の記録」と、一行「ここはあなたが書く。AI は書かない」だけ |
   | 検証 | 検証 | Verification | 説明一行:「主張と原稿の検証の結果を、致命・重要・軽微の順に置く」 |
   | 設定 | 設定 | Settings | 表: 科目 / AI 利用条件(未設定) / 根拠 / 執筆要項の書式(未取り込み)。説明:「条件は、このタブに『科目の条件: 許可(または 限定・不明・禁止)』『根拠: シラバスの該当箇所』とコメントして決める」 |
   | 開示と提出前 | 開示と提出前 | Disclosure and submission | 提出前のチェックリスト(`- [ ]`)と、一行「最後に『提出を確認』とコメントする」 |

   作り方は Docs の guide の topic.tabs「AT BIRTH」のとおり(タブごとに file と node を作り、`project` の `$lid:p` に `tabs` の patch を当てる)。
4. 作ったらすぐ、Artifact の `open` で文書を開いて学生に見せる。
5. **文書を登録する**: `read( ref = {"object":"project","id":"<doc id>"} )` を一度呼ぶ。フックがサーバーの応答からタブの名前を確かめ、`.ryukoku/docs.json` に控える(AI はこのファイルに書けない)。応答の後に「登録した」と出なければ、タブの名前が表と違う。直さずに学生に伝える(登録後は AI はタブの名前を変えられない)。
6. 学生に伝える(短く):
   - 文書の「設定」タブに、科目の AI 利用条件とその根拠をコメントで書く(例:「科目の条件: 限定」「根拠: シラバス第1回『調べものと文章の点検には使ってよい』」)。分からなければ「科目の条件: 不明」。決まるまで、AI は原稿に提案としてだけ書く。
   - 入力が学習に使われない設定(オプトアウト)を確かめたら、同じタブに「オプトアウト: 済」とコメントする(ガイドラインⅡ-2(1))。
   - コメントを付けたら、チャットで一言知らせてもらう。AI がコメントの一覧を読むと、フックが判断を記録する。
   - 考えや直感をチャットで話すと、AI が「主張カード」に提案として整理する。自分の主張だと確かめたら ✓ で入れ、その行に「C001 を確認」とコメントする。
   - 非公式の道具で、大学・学部・教員の指示が優先する。他大学なら自校の規程に置き換える。
7. 学生が知らせてくれたら、「設定」タブのコメントを `query` で読む(フックが記録する)。記録された条件を一行で伝える。

## してはいけないこと
- 学生の代わりに RQ・テーマ・主張を決める(`rq-dialogue`・`idea-intake` で問いを返す)
- 判断のように読めるコメント(「確認」「VERIFIED」「提出を確認」「科目の条件: …」)を AI が書く。提案の ✓・✕ を AI が押す(どちらもフックが止める)
- ブラウザや画面の操作の道具で claude.ai の文書を開く・押す(フックが止める。そこでの操作は学生の操作として記録されてしまう)
- 科目の条件を推測で決める。卒論の字数や書式の数値を、学部の要項を見ずに示す(学部と入学年度で違う。`style-extract`)
- 学生にコマンドを打たせる、合言葉や鍵を尋ねる
