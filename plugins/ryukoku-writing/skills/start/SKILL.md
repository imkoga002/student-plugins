# 始める

講評言語(`.ryukoku/config.yml` の `feedback_lang`)が `en` のときは、学生への応答・問い・説明を英語で書く(この指示文は日本語のままでよい)。

## なぜこの順番か
この Plugin で AI が原稿を書いてよいかは、科目の AI 利用条件で決まる(ガイドラインⅢ-3)。だから最初に一度だけ、学生が自分の端末で `./rk setup` を実行し、シラバスの条件とその根拠を記録する。AI が書いた段落は自動で記録され、開示の事実になる(Ⅲ-4)。合言葉が要るのは VERIFIED と提出前の最終確認だけで、登録は後回しにしてもよい。合言葉はチャットに決して入れさせない(AI が知れば、原典を読んだという宣言を装える)。

## 手順
1. 学生に尋ねる(まとめて一度に。推測で埋めない):
   - 論文用のフォルダ(今のフォルダでよいか。ホームフォルダそのものや Plugin の中は不可)
   - 原稿の言語(ja / en)と、講評を受けたい言語(ja / en。別にしてよい。Plugin の設定の既定は `${user_config.feedback_lang}`。空なら原稿と同じ)
2. 初期化する(パスは絶対パスで):
   ```
   bash "${CLAUDE_PLUGIN_ROOT}/scripts/init-project.sh" --dir "<論文のフォルダの絶対パス>" --lang ja --feedback ja
   ```
   `${CLAUDE_PLUGIN_ROOT}` が展開されないときは、このスキルの場所から二つ上(`${CLAUDE_SKILL_DIR}/../..`)が Plugin の場所。既に `.ryukoku/config.yml` があれば初期化は止まる(続きは ./rk setup)。
3. 学生に伝える(短く):
   - 自分の端末(ターミナル)を開き、`cd <フォルダ>` のあと `./rk setup` を一度だけ実行する(Windows は `rk setup` か `.\rk.ps1 setup`)。科目の AI 利用条件(シラバス。ガイドラインⅢ-3)とその根拠、学習へのオプトアウトの確認(Ⅱ-2(1))、合言葉(今でも後でもよい)、Git の選択を行う。
   - 合言葉は、その端末と、ローカルの証拠ノートの画面にだけ入れる。チャットには入れない。
   - 終わったら、Claude Code を **その論文のフォルダで開き直す**(別のフォルダで開いたままだと、記録と検知の一部が働かない)。
   - 考えや直感を AI に話すと、主張カード(claims/)に整理される。自分の主張だと確かめたら、証拠ノートの画面でボタンを押して確認する。AI は確認したカードと台帳の文献・保存したデータだけを材料に、科目が許せば執筆を手伝い、主張とのすり替えや根拠の不足を厳密に検証する。
   - 非公式の道具で、大学・学部・教員の指示が優先する。他大学なら自校の規程に置き換える。

## してはいけないこと
- 学生の代わりに RQ・テーマ・主張を決める(`rq-dialogue`・`idea-intake` で問いを返す)
- `./rk setup` などの人間専用のコマンドを AI が実行する(フックが止める。端末がないので動かない)
- 合言葉を尋ねる、チャットで受け取る
- 科目の条件を推測で allowed にする。卒論の字数や書式の数値を、学部の要項を見ずに示す(学部と入学年度で違う。`style-extract`)
