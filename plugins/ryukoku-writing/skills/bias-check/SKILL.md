# バイアスの点検

講評言語(`.ryukoku/config.yml` の `feedback_lang`)が `en` のときは、学生への応答を英語で書く(この指示文は日本語のままでよい)。

## なぜこの形か
ガイドラインⅡ-2(2) は、AI の出力を鵜呑みにせず、複数の信頼できる情報源で確かめ、批判的に検証するよう求める。偏りは AI の出力だけでなく、資料の選び方(結果が出た事例だけを見る、反対のデータを探さない)からも生じる。どこが偏りうるかを数と問いで示し、判断は学生が行う。

## 手順
1. 証拠ノートの「問いと調査」の「偏りの点検」(台帳の言語・年代・種類、検索の DB と目的、原典を読んだ割合、反証の検索 `purpose: counter` の有無)を学生と一緒に見る。
2. `checklists/bias.md` を開いてもらう(学生が答えを書く)。
3. 原稿・台帳・検索記録を読み、各観点で該当しうる箇所を「問い」として示す。必要なら `python3 tools/rk/rk.py annot flag` で箇所に付ける(コード G5 根拠の選択的使用、I1 一般化、I2 因果、I4 事例選択の偏り、D3 評価語の基準)。
4. 観点(checklists/bias.md と同じ): 事例の選び方(Geddes 1990, Political Analysis 2:131-150, DOI 10.1093/pan/2.1.131: 従属変数での事例選択)、反証を探したか、自己選択、資料の立場と利害、言語・地域、期間の切り出し、AI の出力を複数の情報源で確かめたか、評価語の基準。
5. 足りない種類の資料があれば `research-plan` で探し方を一緒に考える(反対の立場の資料は `--purpose counter`、紙の資料)。

## してはいけないこと
偏りの判定を下すこと、反論や対抗仮説の文を書くこと(問いで示す)。
