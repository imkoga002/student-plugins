# 証拠ノート(画面)

講評言語(`.ryukoku/config.yml` の `feedback_lang`)が `en` のときは、学生への応答・問い・説明を英語で書く(この指示文は日本語のままでよい)。

## なぜこの画面か
人間の判断は、学生が内容を自分の目で確かめたうえでの署名でだけ記録される。端末で一件ずつ答えるより、画面で差分や原典の情報を見ながら選び、最後に合言葉を一度だけ入れる方が、手間が少なく確認も深くなる。画面は 127.0.0.1 だけで動き、外に通信しない。

## 開き方(AI が起動してよい)
SessionStart の文脈に、Plugin の場所の絶対パスつきで起動コマンドがある。それをそのまま **run_in_background** で実行する(`--project` は `notebook` の前でも後でもよい):
```
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/rk/rk.py" --project "<プロジェクトの絶対パス>" notebook
```
表示される `http://127.0.0.1:<port>/` を学生に伝える。AI が起動してよいのはインストールされた Plugin のコードだけ(フックがコマンドを解析し、実行するファイルの実際の場所を確かめて、他の場所からの起動を止める。学生が合言葉を入れる画面なので)。画面と端末には、動いているコードの場所と版が出る。学生が自分の端末で `./rk notebook` を実行してもよい。

## 学生に伝えること(短く)
- 各項目の「表示」で内容(差分・原典の情報・前回の署名からの差分)を確かめると、判断を選べるようになる。選んだものは「署名する項目」にたまる。
- 最後に「合言葉で署名」を押し、合言葉を一度入れる。選んだ項目がそれぞれの内容のハッシュつきで署名される。合言葉は保存されず、署名が終わると鍵も捨てられる。
- 全部をまとめて採用するボタンはない。一件ずつ確かめるため。
- 合言葉は、この画面と自分の端末にだけ入れる。チャットには入れない。

## してはいけないこと
- 合言葉を尋ねる。画面の API を Bash で呼ぶ(フックが止める)。
- 「全部採用でよい」と勧める。どれを選ぶかを学生の代わりに決める(内容の説明はしてよい)。
