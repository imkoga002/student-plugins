# 表記・書式の提案

講評言語(`.ryukoku/config.yml` の `feedback_lang`)が `en` のときは、学生への応答・問い・説明を英語で書く(この指示文は日本語のままでよい)。

## なぜ提案なのか
AI は manuscript/ に書き込まない(フックがすべての道具で止め、ツール実行中の変更も検知する)。表記の機械的な統一でも同じで、学生が一か所ずつ差分を見て採否を決め、合言葉で署名する。採用した箇所は開示の記録に自動で残る。こうすると、提出物に入る変更はすべて人間が見たものになる(ガイドラインⅢ-4)。

## 提案の種類(道具が作るときと採用するときに検査する)
| kind | 変えてよいもの | 変えられないもの |
|---|---|---|
道具は「許可した変換だけで両方を同じ形にそろえ、一字でも違えば拒否する」方式で検査する。行の数も変えられない。

| kind | 変えてよいもの(これだけ) | それ以外はすべて拒否(例) |
|---|---|---|
| format | 英数字・カナの全角半角、句読点の組(「、」と「，」、「。」と「．」。数字の間の点とカンマは除く)、日本語の文字の周りの空白、行頭の全角空白 | 語・数字・小数点・符号・演算子・矢印・○×・％・引用符・括弧・Markdown の記号(`>` `#` `~~` `<!-- -->` `$` `^[` `|`)、英語の語の間の空白、行頭の字下げ、句読点の追加・削除・移動、見えない文字(ゼロ幅など)、形の似た別の文字 |
| citation | format の変換 + 既存の括弧の引用 ↔ 同じ文献の `[@key]`(references.json の著者の姓と年が一致。頁・接頭辞・接尾辞はそのまま) | 新しい引用の付加、引用の削除・移動、別の文献への差し替え、頁の付加・変更、`contra` などの付加 |
| diagram | ```mermaid の front matter(theme・look・layout)の行の追加・削除 | 図の中身(矢印の向き・語・ノード) |
| heading | format の変換 + 見出しの番号 | 見出しの語、見出しの段(`#` の数) |

## 手順
- 承認済みの記法規則で機械的に直す(最優先。AI の判断が入らない): `python3 tools/rk/rk.py propose style manuscript/<file>.md`
- Mermaid の固定: `python3 tools/rk/rk.py propose mermaid manuscript/<file>.md`
- それ以外の表記の統一:
  1. `python3 tools/rk/rk.py propose start manuscript/<file>.md`(写しのパスが出る)
  2. 写し(proposals/.work/…)を Edit で直す。表記・書式だけ
  3. `python3 tools/rk/rk.py propose finish <token> --kind format --why "<規則と理由を一行>"`
- 作ったら学生に一、二文で伝える: 「証拠ノートの『提案』で一か所ずつ差分を見て採否を選び、最後に合言葉で署名する(端末なら `./rk apply`)」。`./rk apply` を AI が実行しない。

## 内容の直しを頼まれたら(「学術的に」「自然に」「わかりやすく」など)
- 語・文・論証を変える直しは提案にできない(道具が拒否する)。理由を一文で伝え、提案ファイルは作らない。代わりに箇所・基準・問いを示す(`review-comments` の annot flag)。修正例の文は書かない。
- 表記の揺れ(同じ語の漢字とかなの混在など)は語の変更に当たるので提案にしない。箇所を示して学生が選ぶ。

## 失敗したとき
- 「提案にできない変更がある」: 内容か意味に関わる記号が変わっている。表記の部分だけに分けて作り直す
- 「原稿が変わったので propose start からやり直す」: 写しの後に学生が書き進めた。学生の変更を消さないために作り直す
