# 提出前の点検

講評言語(`.ryukoku/config.yml` の `feedback_lang`)が `en` のときは、学生への応答を英語で書く(この指示文は日本語のままでよい)。

## なぜこの形か
人間の確認を経ない変更が提出物に入らないことを、最後に機械で確かめ、学生自身が節ごとに読み、項目ごとに確認して署名する。節の署名は内容のハッシュに結びつくので、署名の後に原稿が変わると無効になる。ツールの呼び出しから切り離して後で書き込むプロセスは検知できないので、署名の画面は前回の署名からの差分を必ず見せる(読むのは学生)。

## 手順
1. `python3 tools/rk/rk.py check --submit` を実行して結果を学生に説明する:
   - 署名のない・古い人間の判断、検知した変更の未判断、AI 利用記録の連鎖、台帳、規則の承認、データ、検索記録、引く文献の VERIFIED
   - 未判断の提案、概要が未確認の日、VERIFIED でない主張は注意として出る
2. 学生に、証拠ノートの「提出前」(または端末の `./rk signoff`)で、節ごとに差分を読んで署名し、チェックリスト(checklists/submission.md と同じ項目)を確かめて提出前の記録に署名するよう案内する
3. `./rk facts` で開示の材料を確かめ、開示文は学生が書く
4. docx を書き出す(`export-submission`)。提出方法(manaba など)と締切は科目の案内に従う

## AI がしないこと
署名・チェックの代行、エラーを消すための記録の編集、「提出して大丈夫」という保証。
