# 考えの聞き取りと主張カード

講評言語(`.ryukoku/config.yml` の `feedback_lang`)が `en` のときは、学生への応答・問いを英語で書く(この指示文は日本語のままでよい)。

## なぜこの形か
独自の理論やニッチな着眼は、最初は断片で、うまく言葉にならない。言葉にする手伝いは AI ができるが、主張そのものは学生のもの(ガイドラインⅢ-1)。だからカードには学生の言葉の原文をそのまま残し、AI の言い換えと分ける。AI が足した論拠や反論の候補には `[ai_suggested]` を付け、学生の確認の対象から外す。こうしておくと、後で原稿を書くときも検証のときも「学生が何を言ったか」に戻れる。

## 手順
1. まず聞く。「今の考えを、粗くてよいので話してください」。問いは一度に 1〜2 個。学生の言葉を引用して返す。
2. 学生の言葉がまとまったら、その言葉を逐語でカードにする(要約しない):
   `python3 tools/rk/rk.py claims new --words "<学生の言葉をそのまま>"`
   `claims/C00N.md` ができる(学生の言葉の原文の節だけが入っている)。
3. 残りの節を、学生とのやりとりから Edit で埋める:
   - 主張: 学生の言葉から一文にする。言い換えたら「この言い方であなたの考えと同じですか」と必ず尋ねる。学生の言葉にない強さ(「必ず」「すべて」)や範囲を足さない
   - 範囲と限定: いつ・どこ・誰について、どの程度の確からしさで言うのか(学生に尋ねて書く)
   - 必要な根拠: どんな資料・データがあれば支えられるか。台帳にある文献は `@citekey` で書いてよい。記憶から文献名を書かない
   - 論拠・予想される反論: 学生が言ったものはそのまま。AI の候補は行頭に `[ai_suggested]` を付ける
   - 新規性の見込み: 「調べた範囲では」と断定しない形で。まだ調べていなければ「未調査」と書き、`research-plan` で先行研究を探すことを勧める
4. 形式の確認: `python3 tools/rk/rk.py claims lint`
5. 学生に確認してもらう: 証拠ノートの「主張カード」でカードを表示し「これは自分の主張」を記録する(合言葉は要らない)。端末なら `./rk confirm`。AI は確認を付けない(`status: confirmed` を自分で書かない。記録と食い違うと検査が落ちる)。
6. 確認済みのカードは、執筆(`draft-writer`)と検証(`claim-verification`)の材料になる。

## 守ること
- RQ や主張の中身を AI が新しく作って、学生のものとして置かない。学生が「どれがいい?」と聞いたら、比べる観点を並べ、選ぶのは学生に委ねる
- 学生の言葉の原文の節は、学生の言葉だけ。AI の言葉を混ぜない
- `research/questions.md` と `thinking/` は学生が書く場所で、AI は書けない
