# proposals/(表記・書式の提案)

科目が許せば、AI は表記・書式を原稿で直接直してよい(由来は記録される)。一か所ずつ差分を見て決めたいとき、
内容が変わらないことを道具で保証したいときは、ここに統一差分(.diff)として置く。語・数字・引用符・ブロック引用・隠す記号・
取り消し線・数式記号・文末の？！を変える提案と、新しい引用を足す提案・引用先を変える提案は、道具が作れない
(作るときと採用するときの二度、検査する)。

- 見て決める: 証拠ノートの画面の「提案」(自分の端末で `./rk notebook`)。一か所ずつ「表示」して差分を読み、
  採用・不採用を記録する(合言葉は要らない)。端末なら `./rk apply`(一か所ずつ y / n)。全部まとめて採用する操作はない。
- 採用した箇所だけが原稿に反映され、判断の記録(.ryukoku/signoffs.jsonl)、由来の記録(.ryukoku/provenance.jsonl。
  「AI の提案(書式)」)と disclosure/ai-involvement.jsonl に残る。
- 決め終わった提案は proposals/done/ に移る。
- `style-rules.yml`: 執筆要項などから抽出した記法規則の提案。学生が承認したものだけが .ryukoku/style.yml に入る。
