# ryukoku-writing

龍谷大学の学生が、日本語または英語でレポート・卒業論文を書くときに Claude Code で使う Plugin です。中心にある考えは一つです: **主張の主はあなた、文章化は AI と速く、検証は厳密に、記録は正直に。** AI があなたの主張や理論を厳しく確かめるので、独自の理論やニッチな着眼を安心して言葉にできます。English: [README.en.md](README.en.md)

> **龍谷大学の公式の道具ではありません。** 龍谷大学の名称は、対象とする学生と規範(龍谷大学「生成AIの活用に関する学生向けガイドライン」2025-11-14)を説明するためにだけ使っています。校章などは使っていません。ガイドラインの読み方はこの Plugin の作成者の解釈で、大学の公式見解ではありません。**大学・学部・担当教員の指示が常に優先します。** とくに科目ごとの指示(ガイドラインⅢ-3。シラバスや授業での指示)に従ってください。ガイドラインは改訂されます(Ⅳ)。`python3 tools/rk/rk.py guideline-check` で更新を確かめ、Plugin の更新も確かめてください。他大学の学生が使うときは、自校の規程に置き換えてください(`.ryukoku/config.yml` と各スキルの記述)。

## 脅威モデル(何から守り、何から守らないか)

この Plugin のフックが相手にしているのは、**ふつうに使っている間の AI の誤り・近道・捏造**です(科目が禁止なのに原稿を書く、記録や設定に書き込む、確かめていない文献や数字を足す、あなたの確認を装う、など)。フックは、決意した攻撃者や、**あなたが実行を許可したプログラム**に対する砂場(サンドボックス)ではありません。許可したプログラムは、あなたの権限で何でもできます。

守りは二段です。(1) フックが、見分けられる形の操作を事前に止めるか確認を出す。(2) すり抜けたものは、後から見つける: ツールの実行中の変化の検知(msguard)、`./rk check`、CI。後からの検知が最後の歯止めで、記録と検査を読み、判断するのはあなたです。下の「保証すること」は、この枠の中での保証です。

## 導入

```
/plugin marketplace add imkoga002/student-plugins
/plugin install ryukoku-writing@student-plugins
```

端末からは、Claude Code の CLI で次のようにも入れられます(`--marketplace` は、まだ追加していないマーケットプレイスを先に追加します。開発時に `claude plugin install --help` で確かめた形です。お使いの版のヘルプで確かめてください)。

```
claude plugin install ryukoku-writing --marketplace imkoga002/student-plugins
```

必要なもの: Claude Code、bash(macOS・Linux・Windows の Git Bash)、Python 3(標準ライブラリだけ)。任意: pandoc(Word・LaTeX・PDF への書き出し)、LuaLaTeX と TeX Live の collection-langjapanese(日本語の PDF)、mermaid-cli の mmdc(図の画像化)、Git と GitHub。

## 考え方

- **主張はあなたのもの。** 断片的な考え・直感・ニッチな着眼を AI に話すと、AI が問いかけながら主張カード(`claims/C001.md`)に整理します。カードにはあなたの言葉の原文がそのまま残り、AI の言い換えと分かれます。AI が足した論拠や反論の候補には `[ai_suggested]` の印が付きます。「これは自分の主張」という確認は、あなたが画面のボタン(または `./rk confirm`)で付けます。AI は付けられません。研究の問い(RQ)と主張の中身を AI が新しく作って、あなたのものとして置くことはしません(問いの立て方を一緒に考えることはします)。
- **検証は厳密に。** AI は主張カードと原稿の段落を、論理(Toulmin の要素、飛躍の 4 類型、誤謬、因果推論の誤り)、根拠の対応(引用・台帳の状態・保存した抜粋が本当に支えるか)、反証の検索、新規性の位置づけ、そして **AI の文があなたの主張をすり替えていないか** の観点で検証し、重大度(致命・重要・軽微)と根拠つきで `review/verification/` に残します。修正案も出します。抜粋がなければ「未照合」、検索していなければ「未調査」と書き、推測で「支える」とは言いません。
- **文章化は速く(科目が許すとき)。** 科目の AI 利用条件(`.ryukoku/config.yml` の `ai_policy`)で、原稿への AI の書き込みが変わります。

  | ai_policy | 原稿への AI の書き込み |
  |---|---|
  | `allowed` | 書いてよい。書いた段落の由来が自動で記録される |
  | `limited` | 書く前に毎回確認が出る(何が許されているかをシラバスで確かめる) |
  | `unknown`(既定) | 書く前に毎回確認が出る(シラバスの確認を促す) |
  | `prohibited` | 書かない。主張カードの作成と表記の提案もしない。調査・検証(修正案の文は出さない)・形式の確認はできる |

  AI が書くときの材料は、あなたが確認した主張カード・論証図・台帳の文献・保存したデータだけです。材料にない主張・数字・文献は本文に足さず、「追加の提案」として本文の外に並べます。
- **記録は正直に。** AI が原稿を書いた・直したときは、どの節のどの段落かを、フックが `.ryukoku/provenance.jsonl`(追記だけ。行ごとに前の行のハッシュ)に自動で残します。警報ではなく記録で、`./rk facts` が「AI が書いた段落の割合・節ごとの内訳・用途」を開示の事実として出します。あなたの編集は、AI のツール実行の間の差分から推定して記録します(推定であることも記録に残ります)。書いた直後には機械の照合(引用の台帳の状態、引用のない断定、出典のない数字、主張カードとの食い違いの候補)が回り、AI が結果を示します。
- **捏造を仕組みで防ぐ。** 記憶から文献・統計・頁を出しません。文献は識別子で実在を確かめ(DOI → Crossref / DataCite、NCID → CiNii Books、CRID → CiNii Research、NDL ID → NDL サーチ)、台帳(`sources/register.csv`)に IDENTITY_CONFIRMED として残します。**書き出しの文献一覧は台帳から作ります**: 機械の照合が登録機関から記録した書誌(`sources/identity.json`。Crossref・DataCite の題名・著者・編者・年・誌名など、CiNii・NDL の題名)を優先し、記録の無い欄は台帳の値を使います。`sources/references.json` は pandoc に渡しません(台帳との違いは `./rk check` が知らせるだけ)。あなたの VERIFIED は、文献一覧に出るその形(登録機関の書誌を含む)そのものを覆うので、出る形が変われば VERIFIED は外れます(書き出しは注意、提出の段階の検査はエラー)。一つの引用キーは台帳の一つの行だけを指します。書き出しは pandoc の利用者のデータフォルダ(`~/.local/share/pandoc` のテンプレートなど)を使いません。原稿が引く文献(`[@key]`・`@{key}`・`nocite`。`nocite: '@*'` なら IDENTITY_CONFIRMED の台帳の行すべて)が台帳にない、IDENTITY_CONFIRMED 未満、または台帳の行に題名と名前(著者・編者・発行者)が無いと、提出の段階の `./rk check` と書き出しのエラーです(下書きでは注意)。引用キーは pandoc の規則で読みます(`[@山田2020]` のような漢字・かなのキーも)。文献一覧や書式を差し替えうる指定(`references`・`bibliography`・`csl`・`citation-style`・`citation-abbreviations`)は、front matter に限らず本文の途中の YAML の塊にあってもエラーで、書き出しは自分で作った設定で上書きもします。TeX・OpenXML・HTML の生のブロックで文献一覧を作る形(`\bibitem` など)もエラーです。地の文で書いた「著者(年)」や、普通の文で打った文献の一覧は、機械では照合できません。原稿の数字は、**文ごとに**、引用か、`data/raw|processed/…` の**AI のツールが書いていない**ファイル(`data/raw/` は `rk.py data add` の台帳に同じ内容で載っているもの)への参照があるか、`data/numeric-claims.csv` の**確かめられる行**(データのファイルが同じ条件を満たし、キーの行が一つで、値が一致する)に載っているか、あなたが端末で「出典は要らない」と印を付けたか(`./rk figures`。文が変わると外れる)を確かめ、無ければ下書きで注意、提出の段階でエラーにします。確かめられない `numeric-claims.csv` の行は `./rk check` が知らせます。数字の候補は本文のすべての数(算用数字と、助数詞の付く漢数字)で、除くのは、年(「年」「年度」「年代」が付くもの、日付の形、年の範囲、`in 2020` のような英語)・日付・時刻・図表や式や節の番号・版の番号(`v`・`ver`・`version` が前にあるか、Python・R・SPSS などの名前の後)・規格の番号(ISO など)・序数(第1位・2回目・1人ずつ)・調査の設計の要素の数(N 段階・N 群・N 問・N 項目・N 件法・第 N 波)・見出しやコードの中の数だけです。4 桁の数は、上の年の形でなければ数えます(「有効回答数は 1523」「n = 2000」)。言葉で書いた数(「三つ」「three」「半数」)は漏れます。
- **合言葉の署名は二つだけ。** VERIFIED(原典を読んで確かめたという宣言)と、提出前の最終確認(内容と AI 利用の開示が正しいという宣言)。ほかの判断(主張カードの確認、提案の採否、コメントの解決、記法規則の承認、節を読んだ確認など)は、画面のボタンか端末のキー一つで、判断した内容のハッシュに結びついて記録されます。
- **調査は記録とともに。** 検索の道具は、`research/questions.md` にあなたが書いた問いの番号に結びつけてだけ動き、検索のたびに記録(DB・検索式・日付・件数・問い・目的)を自動で残します。反証の検索(`--purpose counter`)も同じに残ります。
- **確認なしで動くのは、許可リストのものだけです。** AI のシェルのコマンドのうち、確認なしで通すのは (a) Plugin 同梱の道具(中身が同梱のものと一致するときだけ)と、(b) 読み取りだけの決まったコマンド(`ls`・`cat`・`grep`・`git status`・`git log` など)だけです。それ以外の実行と、解析しきれない書き方には、コマンドを名指しして確認が出ます。中身を読み、必要なときだけ許可してください。

ガイドラインⅢ-4 は、生成 AI で作ったものを自分の成果物として出すことを戒めています。この Plugin は、AI が書いた部分を隠さず開示できるよう記録し、科目が許すときだけ原稿の執筆を手伝います。**AI の利用を記録し開示できることは、ガイドラインⅢ-4(AI の作成物を自分の成果物として出さない)を満たしたことと同じではありません。** 開示するのも、科目の規則に従うのも、あなたです。科目の指示に従い、開示の方法は担当教員に確かめてください。これは Plugin の作成者の解釈であり、大学の公式見解ではありません。

## はじめての手順(端末を開くのは一回)

1. Claude Code に `/plugin marketplace add …` と `/plugin install …`(上の導入)
2. 論文用のフォルダで Claude Code を開き、`/ryukoku-writing:start`(または「卒論のプロジェクトを始めたい」)。言語を答えると、AI がフォルダを初期化します
3. 自分の端末(ターミナル)を開き、そのフォルダで **`./rk setup`** を一度だけ実行します(Windows の cmd は `rk setup`、PowerShell は `.\rk.cmd setup`。PowerShell の既定の実行ポリシーでは `.\rk.ps1` は動かないことがあります。**Windows では setup も画面もまだ実機で試していません**)。科目の AI 利用条件とその根拠(シラバスの記述などを一行)、学習へのオプトアウトの確認、合言葉(今でも、最初の VERIFIED のときでもよい)、Git の選択(Git の名前とメールが未設定なら、ここで尋ねます。実名でなくてかまいません)を行います
4. **Claude Code をそのフォルダで開き直します**(別のフォルダで開いたままだと、記録と検知の一部が働きません)
5. 考えを AI に話します。AI が主張カードに整理したら、自分の端末で `./rk notebook` を実行し、端末に出た鍵つきの URL(`http://127.0.0.1:…/#k=…`)をブラウザで開きます。「主張カード」のタブで自分の主張だと確かめて「記録する」を押します。画面の鍵はその端末にだけ出ます。チャットに貼らないでください(AI は画面を起動しません。鍵が無いと画面の API は何も受け付けません)
6. 科目が許せば、AI に節の下書きや直しを頼みます。AI は確認済みの主張カードと台帳の文献・保存したデータだけで書き、書いた段落の由来と機械の照合の結果を示します。自分で書いてもかまいません
7. 検証を頼み(「この節を主張カードと照らして検証して」)、致命・重要の指摘から直します。原典を読んだら、画面の「文献と主張」で VERIFIED を選び、合言葉で署名します
8. 提出前に、画面の「提出前」(または `./rk signoff`)で、由来と開示文を読み、チェックリストを確かめて、合言葉で最終確認に署名します

## 合言葉について

- 要るのは VERIFIED と提出前の最終確認だけです。`./rk setup` で登録しなかったときは、最初に `./rk verify` か `./rk signoff` をしたときに登録します。
- 10 文字以上で、関係のない 3〜4 語をつなぐか 16 文字以上にします(同じ文字の繰り返し・数字だけ・よくある語が中心のものは登録できません)。公開鍵はプロジェクトにあるので、短い合言葉は PC の上で総当たりされえます。**チャット・AI・メールには決して入れないでください。** 入れる場所は、自分の端末と、ローカルの証拠ノートの画面だけです。
- **合言葉を入れる前に、表示される「動いているコード」の場所と版を確かめてください。** 端末と画面の署名の欄に出ます。人間用のコマンドと画面は、合言葉を求める前に、自分の場所が Claude Code の記録した Plugin の場所(SessionStart のフックが記録します)と同じか、同梱の一覧(MANIFEST)と食い違いがないかを確かめ、違えば合言葉を求めずに止まります。ただし、これは「Plugin のコードが動いているときの確認」です。同じ利用者の権限で動くプログラムは、`./rk` が読む行き先の記録も、確認するコードそのものも書き換えられます(下の「保証しないこと」)。
- **知られたかもしれないとき**(チャットや他人に): `./rk setup` で新しい合言葉を登録します。今の合言葉で新しい鍵を承認してから今までの鍵を失効させ、失効の記録(今までの鍵で署名)に新しい鍵を「引き継ぎ先」として書きます。失効した鍵の承認は、この引き継ぎ先のほかは時刻にかかわらず無効になるので、漏れた合言葉で別の鍵を足されても信頼されません。失効より前の署名は有効のままです。
- **忘れたとき**: `./rk setup` で新しく登録すると、新しい鍵はこの PC の信頼の起点になり、起点の変更が `.ryukoku/root-changes.jsonl` に記録されます。main で commit して、自分の端末から push してください(pre-push が `yes` を求めます)。CI は「起点が変わった」ことと新しい指紋を出力の最初に出します。**指導教員がその指紋をあなたと会って照らすことが前提**です。
- チャットに「合言葉は …」の形で書いたときと、登録した合言葉そのもの(短い一行のメッセージ。全角で書いた場合も)を送ったときは、送信の前に止まります。文の中に混ぜた場合など、それ以外の形は止められないことがあります。
- 別の PC で作業するときは、そこで `./rk trust` を実行し、表示される指紋を最初に控えた指紋と照らします。
- 指紋(`8C77-CA09-…` のような 16 文字)は指導教員にも見せておきます。GitHub の CI は、main の履歴の根の commit がただ一つであることを確かめ、その履歴で最初の `signers.json` の署名者を信頼の起点にして、その指紋を出力の**最初の行**(「【信頼の起点】」)に出します。**指導教員の手順**: PR の CI の出力の最初の行の指紋を、控えた指紋と照らす。違えば、その PR を受け付けずに学生と確かめる。「起点が変わった」の行があれば、学生と会って新しい指紋を照らす。HANDOFF.md(フォルダで受け渡すとき)でも同じ照合をします。

## コマンド

| 自分の端末で(人間専用) | 何をするか |
|---|---|
| `./rk setup` | 最初の設定(科目の AI 利用条件・オプトアウト・合言葉(後でもよい)・Git) |
| `./rk notebook` | 証拠ノートの画面を開く(鍵つきの URL はこの端末にだけ出る。AI は起動しない) |
| `./rk confirm` | 主張カードを読み、自分の主張なら確認する(キー一つ) |
| `./rk verify` | 原典を読んで、文献・主張に VERIFIED などを付ける(VERIFIED は合言葉の署名) |
| `./rk signoff` | 提出前: 由来と開示文を読み、チェックリストを確かめ、合言葉で最終確認に署名する |
| `./rk apply` / `./rk style` / `./rk resolve` | 表記の提案の採否 / 記法規則の承認 / コメントの解決(キー一つ) |
| `./rk changes` | 守られているファイル(道具・設定・記録)の変更の検知を判断する |
| `./rk figures` | 出典の無い数字のうち、出典の要らないもの(自分の調査の設計・例・文書の構成など)に一件ずつ印を付ける(文が変わると外れる) |
| `./rk disclose` / `./rk optout` / `./rk trust` / `./rk import-docx` / `./rk update-tools` | 日ごとの AI 利用の概要 / オプトアウトの記録 / 別の PC での信頼 / 指導教員の Word のコメントの取り込み / Plugin の更新の反映 |

| 誰でも(AI も) | |
|---|---|
| `./rk check` | 構造の検査(CI と同じ)。`--submit` で提出前の検査 |
| `./rk facts` | AI 利用の開示のための事実の一覧(由来の記録から、AI が書いた段落の割合・節ごとの内訳・用途も) |
| `python3 tools/rk/rk.py claims new|list|lint` | 主張カードの作成・一覧・形式の確認 |
| `python3 tools/rk/rk.py provenance materials|show` | 執筆の材料の記録 / 段落ごとの由来の表示 |
| `python3 tools/rk/rk.py verification scaffold|lint` | 検証のひな形(機械の照合つき)/ 形式の確認 |
| `python3 tools/rk/rk.py search …` | データベース検索(毎回、検索の記録が自動で残る) |
| `python3 tools/rk/rk.py refcheck check` | 文献の機械的な実在確認(確かめた書誌を `sources/identity.json` に残し、書き出しの文献一覧はそこと台帳から作る) |
| `python3 tools/rk/rk.py export docx` | Word に書き出し(LaTeX・PDF も) |
| `python3 tools/rk/rk.py bundle` | Git を使わずに指導教員に渡すときの HANDOFF.md(署名者の指紋と検査の結果) |

## この Plugin が保証すること・しないこと

上の脅威モデルの枠の中での保証です。フックが動いていて、あなたが許可していない操作について述べます。

**フックが事前に止めること・確認を出すこと**
- 科目の条件が `prohibited` のとき、AI の Write・Edit・MCP などの道具での原稿への書き込みを止めます(最後の部分がシンボリックリンクのファイルはたどって判定します。MCP などの道具は入力を JSON として読み、配列や入れ子の中も含めて、本文の欄(`content`・`old_string`・`new_string`・`text`・`body` など)の値を除くすべての文字列のうち、パスの形のもの(絶対パスは空白を含んでも、`file://` の URL も)とパスを示す名前の欄の値を見ます。相対パスは行き先が分からないので確認、`prohibited` では止めます)。`limited`・`unknown` では書く前に確認が出ます。設定(`.ryukoku/config.yml`)が無い・読めない・UTF-8 でない、`ai_policy` の行が二つある(字下げした行も数える)、行が「`ai_policy: allowed`」の形でない、**AI のツールの実行中に守られた場所(設定・記録・台帳・道具など)が変わった検知が一件でも未判断**、のどれかなら、原稿への書き込みを止めます。検知の判断は、あなたが端末(`./rk changes`・`./rk sign change …`)か画面で記録したものだけが数えられます(AI のツールの実行中に記録のファイルに現れた行は、判断として数えません)。フックと `./rk check` は同じ判定を使います(`rklib/common.py` の `config_problems`)。
- シェル(Bash・PowerShell)からの書き込みのうち、**見分けられる書き方**(リダイレクト、`tee`・`cp`・`mv`・`sed -i` などの書き込みのコマンド、`-o` で書き出すコマンド)は、字句解析した後のパスで判定し、原稿・`.ryukoku/`・台帳・道具・CI・書き出しの設定・問い・思考の記録などに届くものは条件にかかわらず止めます。**ディレクトリの移動は追いません**: コマンドのどこかに `cd`・`pushd`・`popd`(または展開するとそうなりうる語: 変数、それに当たる glob)が一つでもあれば、そのコマンドの相対パスの書き込み先はすべて「不明」です。不明な書き込み先は、`prohibited` と設定を信用できないときは止め、ファイル名か途中のディレクトリ名が守られた名前(`main.md`・`config.yml`・`register.csv`・`identity.json`・`manuscript`・`thinking`・`.ryukoku`・`pandoc` など)なら止め、それ以外は確認を出します。移動が無ければ、相対パスは道具の作業ディレクトリから解きます。`&&`・`||`・`|` の後の改行は、bash と同じに続きとして読みます。**それ以外の書き方**(アーカイブの展開、`patch`・`git apply`、`xargs`・`find -exec`、`python3 -c` などのインタープリタ、サブシェル、あなたが許可したスクリプト)は、許可リストの外なので確認が出ます(事前には中身を判定しません)。
- AI のツールが、問い・思考の記録・人間の判断の記録・由来の記録・台帳(`register.csv`・`claims.csv`・`identity.json`)・検査の道具・CI と Git フック(`.github/`・`.githooks/`)・書き出しの設定(`pandoc/`)・Claude Code の設定・`~/.ryukoku-writing`・Git と Python の設定・シェルの起動ファイル・PATH 上のディレクトリ・自動起動・`.vscode`・`.envrc` に書き込むことは、どの道具でも止めます。CI・Git フック・書き出しの設定を変えるのはあなたで、AI の外で自分で変え、`./rk sign guarded tools --decision confirmed` で確かめます(書き出しの設定は、確かめるまで `export` が止まります。`pandoc/reference.docx` は比べません)。
- AI のシェルから、この PC に届くホスト(`127.0.0.0/8` と `::1` のあらゆる書き方、`0.0.0.0`、`localhost` の名前、hosts ファイルで loopback を指す名前)への接続を止めます(DNS には問い合わせません)。証拠ノートの画面の API は、起動のたびに作る鍵(あなたの端末にだけ表示する)が無い要求を受け付けません。
- 許可リスト(Plugin 同梱の道具と、読み取りだけの決まったコマンド)の外のシェルのコマンドには、確認が出ます。

**後から見つけること(最後の歯止め)**
- AI のツールが動いている間に原稿が変われば(シェルの回り道でも)、その段落を AI の側の由来として記録します。呼び出しが重なっても、どれかの呼び出しが開いている間の変化は AI の側です。窓の記録の読み書きは排他のロックの中で行います。ロックが 8 秒の間に取れないときは、その呼び出しに確認を出し(閉じる側に倒す)、次に窓が開けるまでの変化を「AI の可能性」にします。記録から漏れた窓の写しが残っていれば、その間の変化も「AI の可能性」です。PostToolUse が来ないままターンが終わった呼び出しの間の変化も「AI の可能性」(uncertain)で、AI の側に数えます。科目が `prohibited` なのに AI が書いた段落が残っていれば、`./rk check` が注意にし、PR と提出の段階ではエラーにします。
- 守られた場所(台帳 `register.csv`・`claims.csv`・`identity.json` と `review/annotations.json` を含む)がすり抜けて変われば、検知して AI 利用記録とこの PC の別の控えに残し、あなたが判断するまで `./rk check` と CI が通らず、原稿への書き込みも止まります(台帳などを Plugin の道具(`rk.py ledger`・`refcheck` など)が書き換えたときは、道具が書いた内容と一致するので検知になりません)。由来の記録・AI 利用記録・コメントの記録に、Plugin の道具が書いたのではない行が AI のツールの実行中に足されたら、検知になります。判断の記録(`signoffs.jsonl`)の軽い確認は、Plugin の学生専用の経路で書いた行か、AI のツールの実行の外で足された行だけを数えます。
- 書き出しと提出の段階の検査は、文献一覧を台帳から作ることと、数字の出典を、上の「捏造を仕組みで防ぐ」のとおり確かめます。
- VERIFIED と提出前の最終確認は、信頼された署名者の合言葉による Ed25519 の署名がなければ成立しません。GitHub の CI は、main の根の commit がただ一つであることを確かめ、その履歴で最初の `signers.json` の署名者(と、記録された起点の変更)から承認でつながる鍵だけを信頼します。
- 提案ファイルは、許可した変換以外では一字も変えられません(試験 test_proposals.AllowList、test_allowlist_trust.HeadingNumbers)。

**保証しないこと**
- あなたが許可したプログラムや命令のすること。あなたの権限で何でもできます(記録・検知の基準・控えを作り直す、Plugin の道具を使って「Plugin が書いた行」に見せる、画面の鍵を読む、疑似端末を作る、合言葉を受け取る画面を偽る、設定でフックを止める、など)。痕跡が残るようにしていますが、止めきれません。確認が出たら中身を読んでください。
- **由来の記録は、フックの強さまでのものです。** フックが動いていない間(無効化・削除)や、フックの外で動くプログラムの書き込みは、記録が誤るか残りません。
- **あなたの編集の帰属は推定です。** AI のツール実行の外で変わった原稿は、あなたの編集として記録されます(切り離して後で書き込むプロセスの書き込みも)。逆に、確認で断った直後にそのターンの間に自分で直した段落は「AI の可能性」になります。
- あなたが読まずに確認・署名すること。**署名のない確認**(主張カードの確認など)は暗号では守られておらず、フックの拒否・実行中の検知・追記だけの検査で守っています。
- 人間専用のコマンドが端末(`/dev/tty`)を要求するのは歯止めで、人がいることの証明ではありません(Linux の Claude Code 2.1.318 では、Bash の道具の子プロセスは `/dev/tty` を開けないことを確かめました。ほかの版・OS では未確認)。
- この PC に届く DNS の名前は、ループバックとして見分けられません(証拠ノートの API は鍵で守っています)。
- 機械の照合(すり替えの候補、引用のない断定、出典のない数字)は語の一覧による候補で、判断ではありません。
- 許可リストのコマンドの組み合わせや、AI が置いた設定・あなたが置いた設定を通した回避の見落としはありえます。
- 執筆の依頼や問いの代行の依頼の検知(送信前の文脈の注入)は語彙による補助で、言い回しを変えると漏れます。
- フックが止まっている間(`disableAllHooks: true`、Plugin の無効化・削除)は何も止めず、記録も検知もしません。`./rk check`・`./rk setup`・CI は無効の設定を見つけるとエラーにします。
- 証拠ノートの画面から作るコメントには本人確認がありません。指導教員のコメントは `./rk import-docx` だけで入ります。
- GitHub の `pull_request` で動くワークフローが、PR の側で書き換えた定義で動くかどうかは確かめていません(**未確認**)。PR が `.github/` を変えているときは、その PR の CI の結果を信用せず、差分を読んでください。非公開リポジトリでブランチ保護を使うには GitHub Pro 以上が要ります(GitHub Docs「About protected branches」https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)。
- 実際の Claude Code での動作の確かめは一部です。`prohibited` の科目で AI の Write がフックに拒否されることは実際に観察しました。モデルがそもそも書き込みを試みるかどうかはモデル次第です(同じ依頼で、試みずに断った回もありました)。SELF-ASSESSMENT.md §2.3。
- AI の応答の質と、Windows・macOS での動作(実機では確かめていません。SELF-ASSESSMENT.md)。

## プライバシーと通信

- フックと検査は外部に通信しません。通信するのは、あなたが許した検索・検証・ガイドラインの更新確認だけです。
- AI 利用の記録にプロンプトの本文は入れません(種類だけ)。由来の記録には段落のハッシュと行の範囲を入れ、本文は入れません。
- J-STAGE の API の応答には保存を制限する規約(第3条5項)があるため、検索の候補の一覧は Git 管理外(`.ryukoku/cache/`)に置き、次の検索・SessionStart・`./rk check` のたびに 24 時間より古いものを消します(PC を使わない間は残ります)。
- 卒論の字数・書式は学部と入学年度で違います。数値は学部の執筆要項から取り込み、あなたが承認したものだけを使います。
