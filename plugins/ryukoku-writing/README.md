# ryukoku-writing

龍谷大学の学生が、日本語または英語でレポート・卒業論文を書くときに Claude Code で使う Plugin です。問いを立て、主張を組み、本文を書くのはあなたです。この Plugin の AI は、問いかけ、資料の調査と実在確認、表記・書式の統一の提案、レビューでの問いを担います。English: [README.en.md](README.en.md)

> **龍谷大学の公式の道具ではありません。** 龍谷大学の名称は、対象とする学生と規範(龍谷大学「生成AIの活用に関する学生向けガイドライン」2025-11-14)を説明するためにだけ使っています。校章などは使っていません。ガイドラインの読み方はこの Plugin の作成者の解釈で、大学の公式見解ではありません。**大学・学部・担当教員の指示が常に優先します。** とくに科目ごとの指示(ガイドラインⅢ-3。シラバスや授業での指示)に従ってください。ガイドラインは改訂されます(Ⅳ)。`python3 tools/rk/rk.py guideline-check` で更新を確かめ、Plugin の更新も確かめてください。他大学の学生が使うときは、自校の規程に置き換えてください(`.ryukoku/config.yml` と各スキルの記述)。

## 導入

```
/plugin marketplace add imkoga002/student-plugins
/plugin install ryukoku-writing@student-plugins
```

端末からは、Claude Code の CLI で次のようにも入れられます(`--marketplace` は、まだ追加していないマーケットプレイスを先に追加します。開発時に `claude plugin install --help` で確かめた形です。お使いの版のヘルプで確かめてください)。

```
claude plugin install ryukoku-writing --marketplace imkoga002/student-plugins
```

必要なもの: Claude Code、bash(macOS・Linux・Windows の Git Bash)、Python 3(標準ライブラリだけ)。任意: pandoc(Word・LaTeX・PDF への書き出し)、LuaLaTeX と TeX Live の collection-langjapanese(日本語の PDF)、mermaid-cli の mmdc(図の画像化)、Git と GitHub。

## 考え方

- **AI は原稿(`manuscript/`)に書きません。** どの道具でも(Bash・PowerShell の書き込みも含めて)フックが止め、すり抜けて変わった場合も「AI のツール実行中の変更」として検知し、あなたが判断するまで検査が通りません。あなたの問い(`research/questions.md`)と思考の記録(`thinking/`)にも書きません。
- **確認なしで動くのは、許可リストのものだけです。** AI のシェルのコマンドのうち、確認なしで通すのは (a) Plugin 同梱の道具(`tools/rk/rk.py`・`./rk` など。中身が同梱のものと一致するときだけ)と、(b) 読み取りだけの決まったコマンド(`ls`・`cat`・`grep`・`git status`・`git log` など)だけです。それ以外の実行と、解析しきれない書き方には、コマンドを名指しして確認が出ます(AI が書いたファイルを実行しうるときは、より強い文面で)。中身を読み、必要なときだけ許可してください。
- **表記・書式の統一も「提案」です。** 英数字・カナと一部の記号(％・（）・：・；・！・？)の全角半角、句読点の組(「、」と「，」、「。」と「．」)、日本語の周りの空白、見出しの番号(番号は道具が段と順番から決め、AI は値を選べません)、図の設定、同じ文献の引用の書式だけが提案になり、あなたが一か所ずつ差分を見て採否を決めます。それ以外の文字(語・数字・小数点・符号・記号・引用の頁)が一字でも変わる提案は、道具が作れません(許可した変換だけでそろえて一字ずつ比べる方式。作るときと採用するときの二度、検査します)。
- **人間の判断は、あなたの合言葉の署名でだけ記録されます。** VERIFIED(原典を読んで確かめた)、提案の採否、記法規則の承認、コメントの解決、節の署名、提出前の確認、日ごとの AI 利用の概要。合言葉そのものも秘密鍵も保存しません(使うたびに合言葉から鍵を作り、使い終わったら捨てます)。`./rk check` と GitHub の CI が署名を照合します。
- **調査は記録とともに。** 検索の道具は、`research/questions.md` にあなたが書いた問いの番号に結びつけてだけ動き、検索のたびに記録(DB・検索式・日付・件数・問い・目的)を自動で残します。AI は結論を出さず、読む候補の一覧を出します。

なぜここまでするのか: ガイドラインⅢ-4 は、生成 AI で作ったものを一部であっても自分の成果物とすることを強く戒めています。「AI が直したことに気づかないまま提出する」ことと「AI があなたの確認を装う」ことを、仕組みとして起こりにくくするためです。

## はじめての手順(端末を開くのは一回)

1. Claude Code に `/plugin marketplace add …` と `/plugin install …`(上の導入)
2. 論文用のフォルダで Claude Code を開き、`/ryukoku-writing:start`(または「卒論のプロジェクトを始めたい」)。言語を答えると、AI がフォルダを初期化します
3. 自分の端末(ターミナル)を開き、そのフォルダで **`./rk setup`** を一度だけ実行します(Windows の cmd は `rk setup`、PowerShell は `.\rk.cmd setup`。PowerShell の既定の実行ポリシーでは `.\rk.ps1` は動かないことがあります。**Windows では setup も画面もまだ実機で試していません**)。合言葉の登録、科目の AI 利用条件、学習へのオプトアウトの確認、Git の選択(Git の名前とメールが未設定なら、ここで尋ねます。実名でなくてかまいません)を行い、合言葉で一度署名します
4. **Claude Code をそのフォルダで開き直します**(別のフォルダで開いたままだと、記録と検知の一部が働きません)
5. 原稿を自分で書きます
6. AI にレビュー・調査・表記の統一を頼みます。AI は問いのコメント、検索の記録と候補、提案ファイルを置きます
7. 判断するときは、AI に「証拠ノートを開いて」と頼みます(AI が画面を起動し、`http://127.0.0.1:…/` を教えます)。各項目の「表示」で差分や原典の情報を確かめて判断を選び、最後に **合言葉を一度** 入れると、選んだ項目がそれぞれの内容のハッシュつきで署名されます。全部をまとめて採用するボタンはありません

ここまでで 7 手順、端末を開くのは 3 の一回です(Linux で確かめた流れ。画面は AI が起動します)。以後の判断は画面でまとめて行えます(端末で一件ずつ決める `./rk apply` なども残しています)。一括の署名で一部が署名できなかったとき(例: 同じ行を変える提案を二つ選んだ)は、項目ごとに「署名した / しなかった(理由)」が出て、署名した項目は一覧から外れます。

## 合言葉について

- 10 文字以上で、関係のない 3〜4 語をつなぐか 16 文字以上にします(同じ文字の繰り返し・数字だけ・よくある語が中心のものは登録できません)。公開鍵はプロジェクトにあるので、短い合言葉は PC の上で総当たりされえます。**チャット・AI・メールには決して入れないでください。** 入れる場所は、自分の端末と、ローカルの証拠ノートの画面だけです。
- **合言葉を入れる前に、表示される「動いているコード」の場所と版を確かめてください。** 端末と画面の署名の欄に出ます。人間用のコマンドと画面は、合言葉を求める前に、自分の場所が Claude Code の記録した Plugin の場所(SessionStart のフックが記録します)と同じか、同梱の一覧(MANIFEST)と食い違いがないかを確かめ、違えば合言葉を求めずに止まります。ただし、これは「Plugin のコードが動いているときの確認」です。同じ利用者の権限で動くプログラムは、`./rk` が読む行き先の記録も、確認するコードそのものも書き換えられます(下の「保証しないこと」)。許可リストの外の実行に確認が出ること、行き先の記録やこの記録の書き換えが変更の検知に残ることで、起こりにくく・気づきやすくしています。
- **知られたかもしれないとき**(チャットや他人に): `./rk setup` で新しい合言葉を登録します。今の合言葉で新しい鍵を承認してから今までの鍵を失効させ、失効の記録(今までの鍵で署名)に新しい鍵を「引き継ぎ先」として書きます。失効した鍵の承認は、この引き継ぎ先のほかは時刻にかかわらず無効になるので、漏れた合言葉で別の鍵を足されても信頼されません。あなたの新しい鍵は CI でも引き続き信頼されます。失効より前の署名は有効のままです。
- **忘れたとき**: `./rk setup` で新しく登録すると、新しい鍵はこの PC の信頼の起点になり、起点の変更が `.ryukoku/root-changes.jsonl` に記録されます。main で commit して、自分の端末から push してください(pre-push が `yes` を求めます)。CI は「起点が変わった」ことと新しい指紋を出力の最初に出します。**指導教員がその指紋をあなたと会って照らすことが前提**です(照らさなければ、なりすましと区別できません)。
- チャットに「合言葉は …」の形で書いたときと、登録した合言葉そのもの(短い一行のメッセージ。全角で書いた場合も)を送ったときは、送信の前に止まります。文の中に混ぜた場合など、それ以外の形は止められないことがあります。
- 別の PC で作業するときは、そこで `./rk trust` を実行し、表示される指紋を最初に控えた指紋と照らします。
- 指紋(`8C77-CA09-…` のような 16 文字)は、初回の面談で指導教員にも見せておきます。GitHub の CI は、main の履歴の根の commit がただ一つであることを確かめ、その履歴で最初の `signers.json` の署名者を信頼の起点にして、その指紋を出力の**最初の行**(「【信頼の起点】」)に出します。**指導教員の手順**: PR の CI の出力の最初の行の指紋を、初回に控えた指紋と照らす。違えば、その PR を受け付けずに学生と確かめる。「起点が変わった」の行があれば、学生と会って新しい指紋を照らす。HANDOFF.md(フォルダで受け渡すとき)でも同じ照合をします。

## 設定

- `.ryukoku/config.yml`(このファイルがあるフォルダでだけ Plugin のフックが動きます): 原稿の言語と講評の言語(別々に選べます)、科目、シラバスの AI 利用条件(`ai_policy: allowed | limited | prohibited | unknown`)。**limited / prohibited にすると道具の動作が変わります**(範囲外の操作に確認が出る / 止まる)。科目の設定でも、本文・問い・主張・結論の代筆は許可できません(この線は Plugin が越えません)。
- Plugin の設定(`/plugin` から): `feedback_lang`(新しいプロジェクトの講評言語の既定)、`crossref_mailto`(任意。既定は空で、Plugin に埋め込みません)、`cinii_appid`(CiNii Research の appid。秘密として扱い、表示・記録しません)。

## この Plugin が保証すること・しないこと

**保証すること(フックが動いている間に、仕組みで止めるか、検知して残すこと)**
- AI のツールが、原稿・問い・思考の記録・人間の判断の記録・検査の道具・Claude Code の設定・`~/.ryukoku-writing`・Git と Python の設定(`.git/`・`.git` という名のファイル・`~/.gitconfig`・site-packages・sitecustomize など)・シェルの起動ファイル・PATH 上のディレクトリ・自動起動・`.vscode`・`.envrc` を書き込むことは、フックが止めます(どのツールでも)。内容が Git/Python の設定の形をした書き込みは、場所を問わず確認が出ます。
- AI のシェルのコマンドのうち、許可リスト(Plugin 同梱の道具と、読み取りだけの決まったコマンド)の外の実行には、確認が出ます。
- AI のツールが動いている間に原稿や守られているファイルが変われば、検知して AI 利用記録(Git で管理し、行ごとに前の行のハッシュを持つ記録)とこの PC の別の控えに残し、あなたが判断して署名するまで `./rk check` と CI が通りません。
- 人間の判断の状態は、信頼された署名者の合言葉による Ed25519 の署名がなければ成立しません。GitHub の CI は、main の根の commit がただ一つであることを確かめ、その履歴で最初の `signers.json` の署名者(と、記録された起点の変更)から承認でつながる鍵だけを信頼します。失効した鍵の承認は、その鍵が引き継ぎ先として署名した鍵のほかは無効です。PR が `tools/`・`.github/` などを変えていれば、あなたの署名した確認がない限り通しません。
- 提案は、許可した変換以外では一字も変えられません。見出しの番号は道具が段と順番から決めます。新しい引用も、引用の頁も足せません(試験 test_proposals.AllowList、test_round4.HeadingNumbers)。

**保証しないこと**
- あなたが読まずに署名すること。署名は「読んで確かめた」というあなたの宣言です。
- あなたが確認で許可した実行。許可したコードや命令は、あなたの権限で何でもできます(Plugin の写しを作って `./rk` の行き先を変える、合言葉を受け取る画面を偽る、検知の基準・記録・控えを作り直す、設定でフックを止める、など)。行き先と同梱の一覧の照合、変更の検知、控えとの照合で痕跡が残るようにしていますが、止めきれません。確認が出たら中身を読んでください。
- 許可リストのコマンドの組み合わせによる回避。許可リストの `git`(読み取りだけ)は、使うリポジトリがこのプロジェクト自身の `.git` のときだけ確認なしで通し、別のリポジトリや設定(`core.fsmonitor` など)を使う形は確認を出します。書き出し(`export`)は、プロジェクトの pandoc の設定をそのまま使わず、許可した項目だけを写して使います(フィルタ・テンプレート・ファイル名で指定する Lua のリーダ・ライタなどは拒否)。pandoc・LaTeX・mmdc は、プロジェクトの外の一時フォルダで動かします(プロジェクトに置かれた設定を読ませないため)。それでも、AI が置いた設定や、学生が自分で置いた設定・環境を通して、許可リストのコマンドが別のプログラムを動かす見落としはありえます。
- 代筆・問いの代行の依頼の検知(送信前の文脈の注入)は、語彙による補助で、言い回しを変えると漏れることが多くあります(検証では新しい言い回しの約半分が漏れました)。最後の歯止めは仕組み(AI は原稿と問いに書けない)です。
- フックが止まっている間のこと。`.claude/settings*.json` の `disableAllHooks: true` や、`/plugin` で Plugin を無効にした・削除した間は、何も止めず、記録も検知もしません。`./rk check`・`./rk setup`・CI は無効の設定を見つけるとエラーにし、SessionStart も知らせます。削除の場合は設定が残らないので、`./rk check` は「Plugin のフックが最後に記録した Claude Code の開始」の日付を出すだけです(その後に使った覚えがあれば、止まっていたことになります)。AI のシェルからの `claude plugin`・`claude config` などの操作はフックが止めます。
- 証拠ノートの画面から作るコメントは、本人確認がありません(学生の名義だけで、署名なし。指導教員のコメントは、端末の署名つきの取り込み `./rk import-docx` だけで入ります)。
- GitHub の CI について: `pull_request` で動くワークフローが、PR の側で書き換えた定義で動くかどうかは、確かめていません(**未確認**。独立検証では、GitHub の一般的な仕様では PR の定義が動くと指摘されました)。そのため、PR が `.github/` を変えているときは、その PR の CI の結果を信用せず、差分を読んでください。非公開リポジトリでブランチ保護を使うには GitHub Pro 以上が要ります(GitHub Docs「About protected branches」https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)。
- ツールの呼び出しから切り離して、後で書き込むプロセス(呼び出しの後に変わったものは、あなたの編集と区別できません)。歯止めとして、節の署名の画面は前回の署名からの差分を必ず見せます。
- AI の応答の質。断り方や問いの質はモデル次第です。
- Windows・macOS での動作は、開発した環境(Linux)では確かめていません(SELF-ASSESSMENT.md の「未検証」)。

## プライバシーと通信

- フックと検査は外部に通信しません。通信するのは、あなたが許した検索・検証・ガイドラインの更新確認だけです。
- AI 利用の記録にプロンプトの本文は入れません(種類だけ)。
- J-STAGE の API の応答には保存を制限する規約(第3条5項)があるため、検索の候補の一覧は Git 管理外(`.ryukoku/cache/`)に置き、次の検索・SessionStart・`./rk check` のたびに 24 時間より古いものを消します(PC を使わない間は残ります)。
- 卒論の字数・書式は学部と入学年度で違います。数値は学部の執筆要項から取り込み、あなたが承認したものだけを使います。
